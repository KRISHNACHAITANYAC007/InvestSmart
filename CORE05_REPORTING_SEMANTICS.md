## B1 — funding-event evidence reconciliation

For each owned journal page, compare RESERVE/SPEND/RELEASE to its settlement_allocation_events. Match event key, action, owning user, allocation reference kind/id and exact summed amount. Each allocation event must resolve to an owned allocation. SETTLED and OPENING_SETTLED are settled-origin sources; other source IDs must resolve to owned CASH_CREDIT obligations with known policy/status. Return **current** obligation status explicitly; it is not a reconstructed event-time cash bucket.

Results: MATCHED means only the funding event's evidence agrees, MISMATCH means a concrete action/reference/amount inconsistency or an ineligible restricted-credit funding source, INCOMPLETE means evidence is absent/unresolved or over the bound, and NOT_EVALUATED means this unit does not evaluate that journal action. None establishes account-wide correctness, profit or a complete statement. No sum across reserve/spend/release is advertised as cashflow.

Retain raw journal magnitudes and actions. Output no fingerprints or foreign-user records. Use active server-authenticated identity, the existing bounded journal pagination, one read-only REPEATABLE_READ/REQUIRES_NEW snapshot and constructor-injected repositories/DTOs. One bound evidence query covers funding event keys on the page, using parameterized owned joins and a maximum of 1000 evidence rows plus one truncation sentinel. If truncated, all evaluated funding entries on that page are INCOMPLETE, with no partial source list presented as complete. Ordering follows the journal page; source rows order by event/allocation ID. No per-event query loop or database initialization.

## Existing journal actions

| Action | Meaning in current writer | Reporting rule |
| --- | --- | --- |
| SETTLED_CREDIT | Credits settled cash | Preserve magnitude; future statement may classify credit with proved coverage |
| WITHDRAW | Settled-only virtual withdrawal | Never confuse with real payment; no reverse inference from current balance |
| PENDING_CREDIT | Creates reusable/restricted obligation | Not settled cash or necessarily profit; link actual obligation evidence in later work |
| RESERVE | Moves eligible source amounts into reservation | B1 matches source events; never count reserve plus its subsequent spend twice |
| SPEND | Consumes already reserved source amounts | B1 matches source events; no additional assumed free-cash debit |
| RELEASE | Returns reservation to original source | B1 matches source events; source's current status is not proof of event-time refund bucket |
| SETTLE | Credits remaining pending amount to settled cash | Allocated/consumed credit must not be credited again; current remaining credit alone cannot reconstruct the past |
| REALIZED_CHARGE | Pays eligible cash first, retains uncovered debt | Parent charge and its CHARGE reserve/spend children are linked accounting evidence, not three expenses |
| LINK_DELIVERIES / other actions | Delivery dependency metadata or another journal producer | Preserve raw action; NOT_EVALUATED by B1, never default to zero cash effect |

Opening cash/legacy reservations are captured at integration time, not a complete cash history. Opening lots may intentionally lack historical cost. Equal timestamps do not prove causal ordering among settlement/refund operations. Unknown/missing evidence must remain explicit rather than being filled with invented balances or trades.
